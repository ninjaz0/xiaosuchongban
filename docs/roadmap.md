# 阶段与验收

任务编号、负责人、状态和依赖以 Multica 为准。本文件描述稳定的验收顺序，不承诺日历交付日期。

## M0 技术与需求验证

冻结首版场景；建立真实 Unity 工程和模块契约；验证透明窗口、LLM 流式接入与可授权的角色样例。所有关键技术结论留下设备、版本和复现记录。

## M1 桌宠与文字对话

一个 VRM 角色、透明窗口、流式文字、情绪事件、配置与会话存储形成闭环。取消、失败恢复和退出可用。

## M2 双管线与语音表现

Live2D 与 VRM 共用接口，完成热切换、流式 TTS、口型和设置界面。验证两套资产映射及连续切换后的资源释放。

## M3 离线陪伴与记忆

本地 LLM/STT/TTS、VAD 打断、三层记忆与人格规则联通。断网验收、记忆纠正/删除和权限拒绝必须实测。

## M4 跨平台交付与研究验收

完成托盘/热键、多屏/全屏、功耗与稳定性测试、Windows/macOS 测试安装包、用户评测和研究成果。签名、公证、对外发布与学校材料提交按凭据、授权和实际窗口处理。

## 完成标准

产物可定位；实际功能可复现；必要测试有证据；未测项明确；人工验收通过。云端演示、Agent 答复、PR 合并或打包成功均不能单独代表整个项目完成。
